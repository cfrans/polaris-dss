Etapa 1 de 6

Prepare o ambiente

O Polaris conecta o monitoramento a um alvo Linux. Comece definindo onde cada parte vai funcionar.

Servidor Polaris
Git e Docker com Compose v2. No Windows e macOS, use containers Linux no Docker Desktop.
Monitoramento
Zabbix 7.0 LTS acessível pelo servidor Polaris. Você pode usar a instalação que já possui.
Alvo de remediação
Um Ubuntu 24.04 LTS com SSH e systemd. O alvo é configurado explicitamente; não é qualquer host do Zabbix.
Comece em um ambiente isolado.

A credencial SSH de serviço tem alcance administrativo no alvo. Use um alvo descartável e acesso de rede restrito antes de habilitar remediações.

Etapa 3 de 6

Conecte o Zabbix

Uma conexão para consultar eventos. Outra para recebê-los. Confira as duas partes.

Acesso ao monitoramento

Basta o IP ou o endereço: o teste procura a API na raiz e em /zabbix, onde ficam as instalações por pacote.

Use o mesmo token no Media Type do Zabbix. Copie o novo valor antes de salvar; depois ele fica mascarado e não poderá ser recuperado pela tela.

Preencha os campos ou carregue os valores do ambiente.

Integração no Zabbix

  1. Template. Em Data collection → Templates → Import, importe o template complementar e vincule-o, junto ao Linux by Zabbix agent, aos hosts pretendidos.
    Baixar template LinuxComo importar templates ↗
  2. Media Type. Em Alerts → Media types → Import, importe o arquivo. Depois abra o Media Type Polaris DSS e, em Parameters, preencha os dois valores abaixo.
    polaris_url — endereço do Polaris visto pelo servidor Zabbix
    http://IP-do-servidor-Polaris:8000/webhook/zabbix
    polaris_token — cole o mesmo valor do campo Token para receber eventos, acima.

    Se você gerou um token agora, copie-o antes de salvar a conexão: depois ele fica mascarado. Se manteve o token salvo, o Media Type continua com o valor anterior.

    Baixar Media TypeComo importar Media Types ↗
  3. Destinatário. Em Users → Users, abra o usuário que receberá os eventos (pode ser o próprio administrador) e, na aba Media, clique em Add:
    Type
    Polaris DSS
    Send to · obrigatório no Zabbix, ignorado pelo Polaris
    polaris
    When active
    1-7,00:00-24:00
    Use if severity
    todas marcadas
    Enabled
    marcado

    Confirme com Add e salve o usuário com Update; sem o Update, a mídia não é gravada.

  4. Trigger action. Crie a ação que envia os eventos ao Polaris. Os valores estão prontos para copiar abaixo.
    Valores da Trigger action

    Em Alerts → Actions → Trigger actions → Create action, preencha:

    Name
    Polaris DSS — encaminhar eventos
    Condição Tag name · equals
    polaris
    Condição Tag value · tag polaris · equals
    enabled
    Condição Template · equals
    Linux by Zabbix agent
    Condição Event name · contains
    Linux: High CPU utilization
    Type of calculation · Custom expression
    (A and B) or (C and D)
    Operations · Send message
    Send to users: o destinatário do passo anterior · Send to media type: Polaris DSS

    A expressão combina (tag name e tag value) ou (template e event name). Se o Zabbix mostrar outras letras ao lado das condições, use as letras exibidas por ele mantendo essa combinação.

    Prefere criar pela API do Zabbix?

    O Polaris não executa esta chamada: ela exige uma credencial com permissão de escrita, que fica com você. Troque os três IDs entre <> pelos valores do seu Zabbix; cada ID aparece no endereço da página de edição do template, do Media Type e do usuário.

    polaris-action.json
    Enviar com sua credencial de administrador do Zabbix

Etapa 5 de 6

Ative a reconciliação

O processo separado consulta o Zabbix e recupera eventos que não chegaram pela notificação.

No servidor Polaris
docker compose up -d polaris-reconciler
docker compose ps

Use 5 a 3600 segundos para ativar ou zero para pausar as consultas. A etapa avança sozinha quando um ciclo recente da reconciliação for concluído; não é preciso salvar de novo.

O processo separado precisa estar em execução no servidor.

Nenhum ciclo de reconciliação conferido nesta visita.

Conexões salvas pelo assistente são lidas pelos dois processos, sem recriar containers. Alterações no arquivo .env ainda exigem docker compose up -d --build polaris-api polaris-reconciler.

Monitorar o próprio servidor opcional

O indicador Servidor do cabeçalho mostra CPU e memória do servidor Polaris lidas pelo Zabbix. Para isso, o servidor precisa de um agente do Zabbix e de um host cadastrado com o template Linux by Zabbix agent.

Deixe em branco e salve para desligar o indicador. Não afeta incidentes nem remediação. Depois da instalação, o host também pode ser alterado em Preferências → Servidor Polaris.

Instalar o agente no servidor Polaris (Ubuntu 24.04)

No servidor Polaris, com uma conta administradora. O comando usa o Zabbix salvo na Etapa 3 e configura o agente com Hostname=polaris-server. Sem um nome válido informado acima, usa polaris-server. Esse é o nome do agente e do cadastro no Zabbix; o nome do sistema operacional não é alterado.

No servidor Polaris

Depois, no Zabbix, crie o host com esse mesmo nome, uma interface de agente com o IP do servidor Polaris e o template Linux by Zabbix agent. A primeira coleta leva alguns minutos.

Etapa 6 de 6

Revise antes de operar

As conexões são parte do caminho. A entrega do evento e os limites de acesso também precisam da sua conferência.

1Veja um evento chegar

No Zabbix, em Reports → Action log, cada envio da ação Polaris DSS — encaminhar eventos aparece com o destinatário, o Media Type Polaris DSS e o status Sent (ou Failed, com o motivo). O mesmo evento deve aparecer no painel do Polaris, em Registros recentes.

Ainda sem alerta? Em um alvo de teste, pare o nginx com sudo systemctl stop nginx, aguarde o incidente e inicie-o de novo.
