Etapa 1 de 6

Prepare o ambiente

O Polaris conecta o monitoramento a um alvo Linux. Comece definindo onde cada parte vai funcionar.

Servidor Polaris
Git e Docker com Compose v2. No Windows e macOS, use containers Linux no Docker Desktop.
Monitoramento
Zabbix 7.0 LTS acessível pelo servidor Polaris. Você pode usar a instalação que já possui.
Alvo de remediação
Um Ubuntu 24.04 LTS com SSH e systemd. O alvo é configurado explicitamente; não é qualquer host do Zabbix.
Comece em um ambiente isolado.

Esta versão ainda não tem login de operadores e usa uma credencial SSH com alcance administrativo. Use um alvo descartável e acesso de rede restrito antes de habilitar remediações.

No servidor Polaris

Etapa 2 de 6

Inicie o Polaris

Configure os arquivos locais, inicie o banco e a aplicação, e só então aplique o esquema de auditoria.

  1. Baixe o modelo e salve como .env na raiz do repositório. Preserve um arquivo existente.
  2. Troque os valores de exemplo de senha e token. Credenciais ficam no servidor, fora do Git.
  3. Prepare os arquivos de chave e known_hosts conforme a etapa SSH antes de iniciar o Compose. Para uso sem alvo, siga a opção de arquivos vazios no guia.

Etapa 3 de 6

Conecte o Zabbix

Uma conexão para consultar eventos. Outra para recebê-los. Confira as duas partes.

  1. Informe a URL completa da API e credenciais de uma conta dedicada no .env. Confira permissões sobre os hosts e métodos da API indicados no guia.
  2. Importe o template complementar e vincule-o junto ao Linux by Zabbix agent nos hosts pretendidos.
  3. Importe o Media Type, configure a URL do Polaris e o mesmo token de recepção do servidor.
  4. Associe a mídia ao usuário destinatário e crie a Trigger action com as condições do guia.

Etapa 4 de 6

Prepare o acesso SSH

Uma chave dedicada ao serviço e uma identidade do alvo conferida por você.

  1. No alvo descartável, prepare a conta de serviço e autorize somente a chave pública.
  2. No servidor Polaris, gere a chave dedicada se ainda não existir. A chave privada permanece nesse servidor.
  3. Compare a impressão digital obtida pela rede com a lida diretamente no alvo. Só então salve secrets/known_hosts.
  4. Confira as permissões da chave e a política sudoers com o administrador, seguindo o guia completo.
Conexão não comprova privilégio seguro.

A política atual permite executar comandos como root por meio de timeout. O teste desta página executa apenas true; não valida permissões de remediação.

Etapa 5 de 6

Ative a reconciliação

O processo separado consulta o Zabbix e recupera eventos que não chegaram pela notificação.

No servidor Polaris
docker compose up -d polaris-reconciler
docker compose ps

Após mudar a configuração, recrie API e reconciliador para que ambos recebam os mesmos valores.

Após alterações no arquivo local
docker compose up -d --build polaris-api polaris-reconciler
Nenhum ciclo de reconciliação conferido nesta visita.

Intervalo zero desativa o processo. Um ciclo bem-sucedido confirma a consulta periódica; a entrega pelo Media Type é conferida separadamente.
