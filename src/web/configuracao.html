Etapa 1 de 6

Prepare o ambiente

O Polaris conecta o monitoramento a um alvo Linux. Comece definindo onde cada parte vai funcionar.

Servidor Polaris
Git e Docker com Compose v2. No Windows e macOS, use containers Linux no Docker Desktop.
Monitoramento
Zabbix 7.0 LTS acessível pelo servidor Polaris. Você pode usar a instalação que já possui.
Alvo de remediação
Um Ubuntu 24.04 LTS com SSH e systemd. O alvo é configurado explicitamente; não é qualquer host do Zabbix.
Comece em um ambiente isolado.

Esta versão ainda não tem login de operadores e usa uma credencial SSH com alcance administrativo. Use um alvo descartável e acesso de rede restrito antes de habilitar remediações.

No servidor Polaris
docker version
docker compose version

Etapa 2 de 6

Inicie o Polaris

Configure os arquivos locais, inicie o banco e a aplicação, e só então aplique o esquema de auditoria.

  1. Prepare Docker e banco pelo guia; as conexões com Zabbix e alvo serão preenchidas nas próximas etapas.
  2. O arquivo .env continua opcional para conexões. Valores do ambiente podem ser carregados pelo assistente sem revelar seus segredos.
  3. Inicialize o acesso administrativo uma vez. Para novas instalações, a chave dedicada pode ser gerada na etapa SSH.

Etapa 3 de 6

Conecte o Zabbix

Uma conexão para consultar eventos. Outra para recebê-los. Confira as duas partes.

Acesso ao monitoramento

Use o mesmo token no Media Type do Zabbix. Copie o novo valor antes de salvar; depois ele fica mascarado e não poderá ser recuperado pela tela.

Preencha os campos ou carregue os valores do ambiente.

  1. Preencha e teste a conexão acima, ou carregue os valores do ambiente. Confira permissões sobre os hosts e métodos da API indicados no guia.
  2. Importe o template complementar e vincule-o junto ao Linux by Zabbix agent nos hosts pretendidos.
  3. Importe o Media Type, configure a URL do Polaris e o mesmo token de recepção do servidor.
  4. Associe a mídia ao usuário destinatário e crie a Trigger action com as condições do guia.

Etapa 4 de 6

Prepare o acesso SSH

Uma chave dedicada ao serviço e uma identidade do alvo conferida por você.

Conexão ao alvo

Somente a chave pública sai do servidor. Autorize-a no alvo; a chave privada fica cifrada no cofre.

Chave pública para o alvo
Gere uma chave dedicada ou carregue a configuração do ambiente.

Compare com ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub no alvo. Consultar a rede não estabelece confiança sozinho.

  1. No alvo descartável, prepare a conta de serviço e autorize somente a chave pública gerada acima.
  2. A chave privada permanece cifrada no servidor Polaris. Para usar um arquivo existente, carregue a configuração do ambiente e utilize o Compose opcional indicado no guia.
  3. Compare a impressão digital obtida pela rede com a lida diretamente no alvo. O teste só autentica após essa conferência.
  4. Confira a política sudoers com o administrador, seguindo o guia completo.

Etapa 5 de 6

Ative a reconciliação

O processo separado consulta o Zabbix e recupera eventos que não chegaram pela notificação.

Use 5 a 3600 segundos para ativar ou zero para pausar as consultas. A etapa só avança após um ciclo ativo verificado.

O processo separado precisa estar em execução no servidor.

No servidor Polaris
docker compose up -d polaris-reconciler
docker compose ps

Conexões salvas pelo assistente são lidas pelos dois processos, sem recriar containers. Alterações no ambiente ainda exigem recriação.

Após alterações no arquivo local
docker compose up -d --build polaris-api polaris-reconciler
Nenhum ciclo de reconciliação conferido nesta visita.

No ambiente, intervalo zero pausa as consultas até a ativação. Um ciclo bem-sucedido confirma a consulta periódica; a entrega pelo Media Type é conferida separadamente.
