# Polaris DSS v1.0.3-experimento

Supersedes v1.0.2-experimento before restarting official collection. A forced-polling CPU rehearsal
revealed that polling omitted the item key/value; an official CPU trigger without polaris_tipo
was classified as unknown even though its webhook was correctly classified from system.cpu.util.

Polling now resolves an unambiguous item on the event host through trigger.get and fetches history
at or before the event clock/ns. It feeds the same normalization fields as the webhook: event/host
identity, tags, trigger text, severity, timestamp, metric key and available historical value. It
never uses today's lastvalue for an older alert. Ambiguous items/hosts and missing history remain
partial evidence rather than guessed values. Explicit tags do not bypass metric compatibility.

Validation: 603 Python tests passed on isolated Linux/PostgreSQL; two optional graph tests skipped.
Fifteen new tests cover all three rules from Zabbix-shaped API responses, normalized field parity,
persistence without approval, historical cutoffs, missing permissions and ambiguous items/hosts.
Read-only candidate validation against real historical events 739, 743 and 745 matched R001, R003
and R002, with historical metric values 96.000239, 0 and 100. No audit record was rewritten.
A post-fix physical forced-polling rehearsal remains required; automated/read-only validation is
not an end-to-end remediation result.

API 1.0.3-experimento; engine 0.3.0; KB 1.0.2; migrations 001–010 and remediation scripts unchanged.
