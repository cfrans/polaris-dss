# Polaris DSS v1.0.2-experimento

Replaces the interrupted v1.0.1-experimento collection. Preserve the previous observations and
restart the complete sample under this revision; do not mix revisions in the experimental cohort.

The reconciler could create an incident before the webhook without a diagnostic plan because it
lacked the API's SSH target and mounts. This affects all three planned rules, not only nginx.
Both services now receive the same target/user and read-only service-key/verified-known-hosts
mounts for diagnostic reads. The reconciliation loop does not approve or execute remediation.

The host launcher refuses injection with inconsistent SSH identity, missing/writable/different
mounts or unreadable files. A pending incident without a plan blocks approval and offers explicit
diagnostic refresh. Missing real evidence produces an unavailable plan with no offered action.
No remediation command, approval invariant, database schema or KPI formula changes.

Validation: 588 Python tests passed in isolated Linux/PostgreSQL; two optional graph tests skipped
because Matplotlib was unavailable. All 43 JavaScript tests passed, including recovery from a
missing plan. Tests cover both ingestion orders and a concurrent duplicate during inspection for
R001, R002 and R003. Physical fault injections remain operator actions; successful automated tests
must not be described as a post-fix physical end-to-end rehearsal.

Identifiers: API 1.0.2-experimento, engine 0.3.0, knowledge base 1.0.2, migrations 001–010.
Remediation scripts and their catalog are unchanged. Preserve the existing randomized round order.

Post-deployment verification on 2026-10-18: SSH diagnostic reads for all three scenarios succeeded
from both API and reconciler; runtime target/mount/readability parity passed; API diagnostic 5/5.
The target was healthy during these checks. No post-fix fault injection or approval was performed
by the agent; operator rehearsals remain required before restarting official collection.
