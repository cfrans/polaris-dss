# Polaris DSS v1.1.0-dev

Development preview of the work completed after the official experiment.

- Individual administrator and operator accounts, with script acknowledgment recorded per account. Remediation continues to require a persisted human approval.
- Six-step setup wizard with connection checks and encrypted configuration storage.
- Read-only audit view with filters, CSV and JSON export, and incident history.
- Per-account display preferences, server resource monitoring and an About view with release information.

Release checks in isolated Linux containers passed 684 Python tests (six optional cases skipped) and 83 JavaScript tests. A fresh PostgreSQL 16.15 database applied migrations `001–013` with none pending, and the API health check reported `1.1.0-dev`.

The [changelog](https://github.com/cfrans/polaris-dss/blob/v1.1.0-dev/CHANGELOG.md#110-dev--2026-11-22) records the changes and their validation scope. See the [installation guide](https://github.com/cfrans/polaris-dss/blob/v1.1.0-dev/README.md) for setup and migrations. Use an isolated evaluation environment. Real Zabbix delivery and remediation on a production system were outside the release checks.

The final 30-run sample in the thesis is documented in the [v1.0.3-experimento release](https://github.com/cfrans/polaris-dss/releases/tag/v1.0.3-experimento).
